# 제조 전력 예측 · 최적화 (Manufacturing Power Prediction & Optimization)

제조기업 전력사용량 **예측 → 오차분석 → 피크저감방안 제안** 공모전 프로젝트입니다.

> 본 레포지토리는 팀 베이스 레포지토리인
> [F00lStack/Manufacturing_Baseline_Enhanced](https://github.com/F00lStack/Manufacturing_Baseline_Enhanced)
> 에서 이어서 진행한 **피크 저감 최적화** 작업을 정리한 것입니다.
> 데이터 전처리, 예측 모델(HGB 포함 여러 모델 비교) 코드는 베이스 레포를 참고해주세요.

## 배경 지식: 왜 "피크"가 문제인가
한국전력은 15분 단위로 측정한 **최대수요전력(피크)**을 기준으로 향후 1년치 기본요금을 산정합니다.
즉 어쩌다 한 번 반짝 전력을 많이 쓰더라도 그 순간의 피크가 1년 내내 기본요금에 영향을 줍니다.
그래서 "평균 사용량을 낮추는 것"보다 **"최댓값(피크) 한 번을 낮추는 것"**이 실질적으로 더 중요하며,
아래 1~4번 최적화 전체가 이 목표(최댓값 최소화)를 각기 다른 방식으로 시도한 것입니다.

## 데이터
- 제조 공장 전력 사용 데이터 (15분 단위 피크 전력, 생산량, 기온, 풍속, 습도, 강수량, 공장인원 등)
- 기간: 2021-01-01 ~ 2021-09-14 (총 6,168행)
  - train: 4,272행 (2021-01-01 ~ 06-27)
  - valid: 912행
  - test: 936행 (2021-08-07 ~ 09-14)

## 예측 모델
- **HistGradientBoostingRegressor(HGB)** 기반 전력 예측 (`Best_Way.py`)
- 성능: MAE 10.16 / RMSE 14.51 / R² 0.94
- 베이스 레포에는 HGB 외에도 DecisionTree, RandomForest, SVR, KNN, MLP, ElasticNet, GradientBoosting, ExtraTrees, Ridge 등 다양한 모델 비교 코드(`*_Test.py`)가 포함되어 있으며, 그 중 HGB가 최종 채택되었습니다.

## 최적화

예측 모델이 맞춘 전력값을 바탕으로, **피크 전력(최대수요전력) 저감**을 위한 4가지 방법을 순서대로 시도했습니다.
공통 전제는 하나입니다 — 우리가 가진 변수(생산량·기온·풍속·습도·강수량·시간정보)만으로 피크를 낮출 방법이 있는가?

### 1. 전력값 재분배 (총생산량 보존)

**질문**: 생산계획은 그대로 두고, 예측된 전력값 숫자 자체를 시간 사이에서 옮길 수 있다면 피크가 낮아지지 않을까?

- **왜 LP(선형계획법)인가**: "최댓값을 최소화"하는 문제는 "어떤 값 z보다 모든 시간대 전력이 작거나 같게 하면서 그 z를 최소화"하는 형태로 바꿀 수 있고, 이는 LP로 깔끔하게 풀리는 전형적 패턴입니다.
- **왜 안전상한을 뒀는가**: 모델 예측에는 오차(MAE 10.16)가 있어 실제로는 예측보다 전력을 더 쓸 수도 있습니다. 그래서 과거 데이터 기준 "이 시간대는 평균적으로 이 정도까지는 써도 안전하다"는 안전선(상한)을 시간대별로 미리 정해두고, 그 선을 넘지 않는 범위 안에서만 재분배하도록 제약했습니다.
- **결과**: 피크 173.08 → **164.00kW로 감소**, 총생산량/총전력량은 그대로 보존. 네 가지 중 **유일하게 수치상 분명한 개선**.
- **한계**: "전력값 자체"를 옮기는 건 실제 공장에서 당장 실행 가능한 액션이 아닙니다(전력은 생산활동의 결과물이지 독립적으로 옮길 수 있는 게 아님). "이론적으로 이 정도까지는 여유가 있다"는 가능성을 보여준 결과로 이해하면 됩니다.

### 2. 생산량 재배치 (±20%, CP-SAT)

**질문**: 그럼 실제로 바꿀 수 있는 "생산량"을 조정하면 피크가 낮아질까? (1번은 비현실적이니, 진짜 조절 가능한 변수로 다시 시도)

- **방법**: 각 시간의 생산량을 80~120% 사이 후보(80, 84, 88…120%)로 바꿔보고, 바뀐 생산량을 HGB에 다시 넣어 예측 피크가 줄어드는 조합을 찾습니다. 생산량은 "이번엔 80% 할까 100% 할까" 식의 딱 떨어지는 선택지 중 고르는 문제라, 연속적인 LP보다 이런 경우의 수를 다루는 데 특화된 **CP-SAT(정수계획)**을 사용했습니다.
- **결과**: 상한초과분 감소율 **0%** — 생산량을 이리저리 바꿔도 HGB 예측 피크가 거의 그대로였음.
- **의미**: 방법이 잘못된 게 아니라, **모델이 생산량 변화에 둔감하다** = 생산량은 피크를 결정하는 핵심 변수가 아니라는 것을 실험으로 확인한 결과입니다. "그럼 뭐가 피크를 좌우하나?"라는 다음 질문으로 이어집니다.

### 3. 매칭 최적화 (유사 사례 참조)

**질문**: 데이터를 뒤져보면 생산량도 비슷하고 날씨도 비슷한데 피크는 훨씬 낮았던 과거 시점이 있지 않을까? 있다면 그때처럼 운영하면 되는 것 아닌가?

- **방법**: 현재 시점과 "생산량 차이가 가장 작은" 과거 시점을 찾고, "기온 ±3도, 습도 ±10%" 조건을 더해 더 비슷한 시점을 선별. 찾은 과거 시점의 실제 피크가 더 낮으면 "개선 사례"로 집계.
- **1차 결과**: 643~913건 매칭, 평균개선 25.75~83.42 — 얼핏 개선되는 것처럼 보임.
- **왜 한 단계 더 검증했나(중요)**: 상위 매칭들을 들여다보니 전부 "한여름 vs 한겨울"처럼 **계절이 완전히 다른 시점**끼리 매칭되어 있었습니다. 즉 생산량·날씨가 비슷해서 개선된 게 아니라, 계절이 다르면 그 계절 자체의 특성(설비 가동 패턴 등) 때문에 피크가 낮아 보이는 착시일 수 있다는 의심이 들었습니다. 그래서 **참고 시점의 생산량을 실제 테스트 시점의 날씨 조건에 대입해 HGB로 다시 예측**하는 재검증을 추가했습니다 — 과거 실측값끼리 비교하면 그 계절·환경의 다른 요인이 섞여 믿을 수 없기 때문에, 모델에 재입력해 "진짜 그 생산량으로 지금 운영했다면 어땠을지"를 공정하게 비교해야 합니다.
- **재검증 결과**: 개선 사례가 643건 중 **24건(3.7%)**으로 급감, 평균개선폭도 **0.43**으로 거의 의미 없는 수준.
- **의미**: 1차에서 보였던 "개선"은 진짜 개선이 아니라, **계절 등 측정되지 않은 요인 때문에 생긴 가짜 신호**였음이 증명됨.

### 4. 안전마진 최적화 (Water-filling LP)

**질문**: 모델이 가끔 실제보다 낮게 예측(과소예측)하는 시간대가 있는데, 이런 위험한 시간대에 미리 여유분(마진)을 더 얹어두면 더 안전하고 효율적이지 않을까?

- **Water-filling이란**: 원래 통신공학에서 "상태가 안 좋은 채널에 자원을 더 많이 배분"하는 기법입니다. 여기서는 **train 기간에 과소예측이 심했던 시간대에 안전마진을 더 많이 배분**하는 아이디어를 그대로 가져왔습니다. 24개 시간대에 한정된 "마진 예산"을 나누는 문제라 LP로 풀었습니다.
- **왜 평탄배분과 비교했나**: train에서 배운 "이 시간대가 위험하다"는 순위가 진짜 믿을만한지 검증하려면 대조군이 필요합니다. 24개 시간에 **똑같이** 나눠주는 방법과 비교해, "똑똑하게 배분한 것"이 실제로 더 나은지 확인했습니다.
- **결과**: 예산이 적을 땐 두 방법이 비슷했지만, 예산 400 이상에서는 오히려 **평탄배분이 더 우수**(개선율 -5%~-19%).
- **의미**: train에서 배운 시간대별 위험순위가 test에서는 재현되지 않음 = 전형적인 **과적합**. 시간대만으로는 "어디가 위험한지"를 안정적으로 예측할 수 없다는 결론입니다.

### 요약 표

| # | 방법 | 핵심 결과 |
|---|---|---|
| 1 | 전력값 재분배 | 피크 173.08→164.00kW, **유일하게 수치 개선** (현실 적용성은 낮음) |
| 2 | 생산량 재배치 | 개선율 0% → 생산량은 피크의 핵심 변수 아님 |
| 3 | 매칭 최적화 | 1차 개선 25.75 → 재검증 시 0.43으로 급감 (가짜 신호) |
| 4 | 안전마진 최적화 | 예산 늘수록 평탄배분이 더 우수 → 과적합 확인 |

### 종합 결론
- 생산량·기온·습도가 비슷해도 피크가 크게 다르고, 시간대만으로도 위험 구분이 안 됨.
- **현재 데이터에 기록되지 않은 다른 요인**(설비 운전방식, 중복가동, 계절적 기기전환 등)이 피크의 핵심 결정요인일 가능성이 높음.
- 1번(전력 자체 재분배)만 숫자상 개선이 있었지만 실행 불가능에 가깝고, 2·3·4번은 "생산량/날씨/시간이라는 관측 가능한 변수만으로는 피크를 설명·저감할 수 없다"는 것을 각기 다른 방식으로 증명함.
- 이는 분석의 실패가 아니라, **데이터 한계를 실험적으로 증명한 결과**로 포지셔닝함(향후 설비 운전방식·중복가동 여부 등 추가 데이터 수집 필요).
